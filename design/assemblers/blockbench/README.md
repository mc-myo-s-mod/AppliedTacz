# Blockbench 편집본

Blockbench MCP로 `../models/`의 공통 1.21.1 전체 모델을 가져온 뒤, 기본 Blockbench 프로젝트 형식으로 내보냈습니다.

- `molecular_assembler_ammo.bbmodel`: 탄약 어셈블러, 109개 큐브
- `molecular_assembler_attachment.bbmodel`: 부착물 어셈블러, 76개 큐브
- `molecular_assembler_gun.bbmodel`: 총기 어셈블러, 181개 큐브
- `molecular_assembler_universal.bbmodel`: Universal 어셈블러, 174개 큐브

정적 모델 4개와 모션 사본 4개는 외장·벨트·작업물에 자체 제작한 `assets/appliedtacz/textures/block/assembler_materials.png`를 사용합니다. 인터페이스 부분만 사용자 요청에 따라 AE2 원본 PNG를 `assets/ae2/`에 복사해 연결했습니다. 이미지는 프로젝트에 중복 내장하지 않습니다.

현재 편집본은 사용자 형상 수정과 하부 케이스의 무지 처리도 보존합니다. 밝은 외장, 짙은 프레임, 보라색 코어는 자체 재질이며, 인터페이스에는 AE2 원본 무늬를 사용합니다. 이 변경은 게임 리소스나 원본 생성기에 적용하지 않았습니다.

부착물 어셈블러의 바닥 롤러는 90도 방향을 바꾸어 좌우 이동용으로 정렬했습니다. 양끝의 흰색 레일은 안쪽을 향하는 얇은 인터페이스 파트로 교체했습니다. AE2 19.2.17의 `part/interface_base` 모델(원본 모델 크레딧: Sea_Kerman)을 재사용했으며, 각 파트는 10×10 면과 전체 두께 2로 축소했습니다.

위 네 파일은 정적 모델 편집본입니다. Java 렌더러가 추가하는 금속 ram/sleeve와 제작 애니메이션은 포함하지 않습니다. Forge 1.20.1 전용 UV 변형도 이 파일에 포함하지 않습니다.

원본 JSON과 생성기는 변경하지 않았습니다. Blockbench의 Java 가져오기는 면의 `forge_data` fullbright 메타데이터를 보존하지 않으므로, 여기서 내보낸 JSON을 게임 리소스에 그대로 덮어쓰지 마세요. 게임 적용 시 해당 메타데이터와 멀티블록 셀 분할을 원본 생성 경로에 반영해야 합니다.

## 제작 모션 미리보기

`animated/`의 `molecular_assembler_*_animated.bbmodel`은 정적 모델과 같은 형상·텍스처를 사용하는 **Free Model 형식의 별도 사본**입니다. Blockbench에서 열고 **애니메이션 → `animation.crafting` → 재생**을 누르면 반복 재생됩니다.

- `ammo`: 탄약 프레스 두 번 압착 후 탄약 두 묶음을 오른쪽 인터페이스로 이송.
- `attachment`: 좌우 작업대에서 각각 압착 후 부착물을 오른쪽 인터페이스로 이송.
- `gun`: 앞·뒤 헤드가 시차를 두고 압착. 완성품을 90도 돌려 왼쪽 벨트에 옮기고, 부품 상자와 함께 뒤쪽 인터페이스로 이송.
- `universal`: X/Z 캐리지가 두 지점에서 압착. 중앙 작업물을 오른쪽 벨트에 옮기고, 양쪽 카세트와 함께 뒤쪽 인터페이스로 이송.

4종 모두 20초 반복 주기입니다. 처음에는 벨트가 비어 있으며, 입구 인터페이스에서 작업물이 트레이·고정구와 함께 나옵니다. 6~12초에는 제작 위치에서 기존 압착 모션이 재생되고, 12.3초부터 출구로 이송됩니다. 트레이와 작업물은 하나의 그룹으로 함께 축소되어 인터페이스 안에서 사라지며, 숨겨진 상태에서 입구로 복귀합니다. 벨트는 입고 0~5초, 출고 12.3~약 18.13초 구간에 움직입니다.

고정된 받침 트레이는 남기지 않았습니다. 기존 pallet/inset/clamp가 작업물과 함께 이동하고, 총기 모델 뒤의 고정 도구 트레이 5개 큐브는 제거했습니다. 총기·범용 중앙 트레이는 좁은 옆 벨트에서 50% 크기로 이송되고 제작 위치에서 원래 크기로 펼쳐집니다. 정적 사본에는 제작 위치의 트레이 형상이 남아 있으며 애니메이션 사본에서만 입출고됩니다.

탄약·총기·범용 모델에는 벨트 끝 입출구 패널을 추가했고, 부착물은 기존 인터페이스를 사용합니다. 각 벨트의 추가 슬랫은 반복 경계의 빈틈을 채웁니다. 새 형상은 정적/모션 사본 양쪽에 있습니다. 축은 상단을 고정한 채 늘어나고, 본체는 고정됩니다.

이 모션은 **Blockbench 미리보기용**이며 Minecraft에서는 아직 재생되지 않습니다. 게임 리소스와 기존 Java 렌더러는 변경하지 않았습니다. 게임 연동 시 별도의 렌더링 처리가 필요합니다.

컨베이어 모션 재생성: 저장소 루트에서 `node design/assemblers/blockbench/add-conveyor-motion.mjs`. 기존 프레스 키프레임은 입고 뒤로 이동해 보존하며, 컨베이어·트레이·작업물 트랙을 다시 만듭니다.

저장 파일 검사: `node design/assemblers/blockbench/check-animations.mjs`. 정적/모션 사본의 큐브·UV 일치, PNG 연결, UV 범위, 애니메이터 연결, 20초 루프 양끝, 벨트 이동, 트레이·작업물·표시 장식의 소속, 입구 등장과 숨김 상태 복귀를 검사합니다.

## 자체 텍스처

- 내장 이미지 생성 도구로 새로 생성했으며, AE2 텍스처를 이미지 입력으로 사용하거나 픽셀을 복사하지 않았습니다. 전체 프롬프트는 `texture-prompt.txt`에 있습니다.
- 생성 PNG는 1254×1254, 논리 UV 크기는 64×64이며, 4×4 재질 칸으로 구성됩니다. 흰색 외장, 흑연 프레임, 은색 축, 고무 벨트, 구리·황동, 파란 렌즈, 보라색 에너지, 표시창 등을 포함합니다.
- PNG는 중복 내장하지 않고 상대 경로로 공유합니다. 파일을 옮길 때 `.bbmodel`과 `assets/` 폴더를 함께 유지하세요. 모션 사본은 상위 폴더의 `assets/`를 참조합니다.
- `apply-texture-atlas.mjs`에 이전 재질 ID에서 자체 아틀라스로 옮기는 매핑이 있습니다. 이미 적용한 모델은 다시 UV를 이동하지 않습니다.
- `restore-interface-textures.mjs`는 로컬 `fork/Applied-Energistics-2_1_21_1`의 원본 `part/interface.png`, `interface_sides.png`, `monitor_sides_status.png`, `interface_back.png`와 `block/interface.png`를 바이트 그대로 복사하고 인터페이스 UV를 복원합니다. 해당 이미지의 출처는 Applied Energistics 2이며, AE2 포크 라이선스는 LGPL-3.0입니다. 인터페이스 PNG는 모두 16×16입니다.
- 이것은 Blockbench 편집용 자산입니다. 게임용 해상도 정리·내보내기·멀티블록 리소스 적용은 아직 수행하지 않았습니다. 텍스처는 교체했지만, 위에 기록된 기존 형상의 출처는 바뀌지 않습니다.
